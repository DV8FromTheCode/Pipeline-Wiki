AI coding assistants wrote much of the code and documentation and had a real influence on the design, working under the direction of the maintainer, DV8FromTheCode, who set the goals and reviewed the results. It was not generated by AI on its own. Treat it as early software: read the docs, test on a throwaway world, and report anything that behaves differently from what is written here.

Pipeline is a launcher for the **vanilla Minecraft Java server** that adds a scripting layer on top of data packs. Instead of writing a Java plugin and installing a modded server, you write small YAML files with a `.pipe` extension inside an ordinary data pack. Pipeline reads those files and wires them into the running server.

## What it does

When you run `java -jar pipeline.jar`, Pipeline:

1. Downloads the official server JAR for the Minecraft version you ask for.
2. Patches a handful of server classes in memory so it can see events, register commands, and open menus.
3. Starts the vanilla server exactly as Mojang ships it, with your packs loaded.

Players connect with the normal, unmodified Minecraft client. Nothing to install on their side.

## What you can build

| Feature | What a `.pipe` file gives you |
|---|---|
| **Commands** | Slash commands with typed arguments, aliases, and a permission check. |
| **Events** | React to joins, chat, block break/place, damage, pickups, deaths, server start/stop, and inventory clicks. Many can be cancelled. |
| **Schedules** | One-shot, repeating, and daily timers. |
| **Storage** | Per-player, per-world, or global key/value data that survives restarts (JSON or SQLite). |
| **Permissions** | Declare permission nodes with defaults, and let players request access that operators approve in-game. |
| **Inventories** | Chest-style GUI menus with custom items and click handling. |
| **Registry** | Custom items with names, lore, enchantments, and attributes; custom block metadata; generated resource packs. |
| **HTTP** | Call external web APIs from an action and use the response. |
| **MCFunction bridge** | Trigger Pipeline events, commands, and storage from regular `.mcfunction` files. |

Logic is written as a list of **actions** (`tell`, `command`, `if`, `for`, `storage.set`, ...) and values use `{{ }}` **expressions** with access to the player, command arguments, and stored data.

## What it is not

- Not a Bukkit/Spigot/Paper/Fabric/Forge replacement. There is no Java plugin API.
- Not a client mod. Custom items are vanilla items with data components; custom network packets are declared but not transmitted yet.
- Not finished. See the "Planned" sections throughout the docs for what is still missing.

## Quick Start

1. Get `pipeline.jar` from the maintainer and put it in an empty folder.
2. Run `java -jar pipeline.jar` (needs Java 21+). First launch downloads and patches the server.
3. Drop your packs into `world/datapacks/`.
4. Use `/pipeline reload` to pick up changes to events, schedules, storage, permissions, inventories, and registry. New or changed commands need a server restart.
